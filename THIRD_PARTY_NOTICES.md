# Third-party notices and distribution decision

**Updated: 2026-11-25.** This is a conservative source and build audit for an offline prototype. It is not legal advice, a grant of rights, or approval to distribute source or binaries. No release package is authorized by this notice.

## Owner decision

- This repository currently declares no project-wide license. Keep that status; do not add an umbrella license until project authorship, rights, and the boundary between project code and dependencies have been reviewed.
- Keep each pinned source's copyright, license, attribution, and file-header text intact. Do not infer that a root license overrides a contradictory file header or a dependency's own notices.
- Before any source bundle or binary release, generate a notice set and SBOM from that exact release configuration. Include the complete applicable upstream license texts, every notice for compiled or linked components, the source revisions and local patches, and the actual runtime libraries shipped with the package.
- Block source and binary releases that include material marked `REVIEW_REQUIRED` until the relevant rights and obligations have been clarified in writing and reviewed by the Owner. The current prototype is not cleared for distribution.
- For a dependency that explicitly offers multiple license choices, preserve the upstream choice text and all corresponding license texts until the Owner and legal reviewer approve the package's treatment. Do not select an upstream license on the authors' behalf.

## Actual Linux Debug and Release build records

The checked-in [Linux Debug dependency inventory](docs/sources/linux-debug-build-dependency-inventory.json) records 9 miner/Core translation units, 256 OpenLibm library translation units, and 802 unique compiler-traversed source/header inputs. The [Linux Release inventory](docs/sources/linux-reference-build-dependency-inventory.json) records 9 miner/Core translation units, 256 OpenLibm library translation units, and 804 unique compiler-traversed inputs. Both contain source and object hashes, compiler commands, static archive members and hashes, per-executable GNU linker maps, selected archive members, dynamic libraries, and Debian package copyright-file hashes. The source checkouts were clean at their pinned commits.

In both configurations, `offline_stratum_miner` links all four Core archive members. Debug links these eleven OpenLibm members: `e_exp.c.o`, `e_fmod.S.o`, `e_rem_pio2.c.o`, `e_sqrt.S.o`, `k_cos.c.o`, `k_rem_pio2.c.o`, `k_sin.c.o`, `s_cos.c.o`, `s_floor.c.o`, `s_scalbn.S.o`, and `s_sin.c.o`. Release links these ten: `e_exp.c.o`, `e_fmod.S.o`, `e_rem_pio2.c.o`, `k_cos.c.o`, `k_rem_pio2.c.o`, `k_sin.c.o`, `s_floor.c.o`, `s_scalbn.S.o`, `s_sin.c.o`, and `s_sincos.c.o`. The first-100-line header scan finds eight FDLIBM/Sun signals and three BSD-style signals among the Debug members, and eight FDLIBM/Sun and two BSD-style signals among Release members; these are notice-triage results, not license determinations. The miner dynamically uses OpenSSL `libcrypto.so.3`; each inventory records transitive runtime libraries and Debian package copyright files. These records describe Debian 13 x86-64 builds only and do not represent Windows 10/11 device testing.

The historical Windows Server 2022 OpenLibm artifacts contain compile databases but not compiler dependency lists or final linker maps. The Windows validation workflow now collects compiler dependency output and per-executable linker maps in each configuration; its artifacts must pass on this branch exact head before they count as current evidence.
