# HooHash V110 CUDA BLAKE3 Stage Evidence

Date: 2026-11-26 (Asia/Taipei)

## Scope

This stage implements only BLAKE3 over the 80-byte header and the 80-byte
header with nonce bytes 76–79 zeroed. These are the nonce-dependent first-pass
digest and nonce-independent matrix seed input used by the pinned HooHash V110
Core source. The CUDA program returns each complete 32-byte BLAKE3 digest.

It does not generate or store the 64×64 matrix, run the FP64 transformation,
produce the final HooHash digest, mine, contact a pool, or benchmark hashrate.

## Fixed full-digest vectors

The expected values were generated by and checked against the BLAKE3 C
implementation at the pinned PEPEPOW Core revision above. The CUDA results were
compared across all 32 bytes.

| Header | Mode | Pinned-Core BLAKE3 digest |
| --- | --- | --- |
| nonce 6 | `header` | `7232d2fdfba6031bba97f015ce7c6cadc582d710342b06be9e16a3953312edeb` |
| nonce 6 | `matrix-seed` | `28d0be17bea0de270743b7c09c785157504aecc287f62e2673051bbadf764d6d` |
| `UINT32_MAX` | `header` | `5549afc7e9658f8a77bea3a2e1fd3ddbad2171ddab0facac8339fec2d4b3075c` |
| `UINT32_MAX` | `matrix-seed` | `28d0be17bea0de270743b7c09c785157504aecc287f62e2673051bbadf764d6d` |

The nonce is little-endian in header bytes 76–79. `matrix-seed` replaces those
four bytes with zero before BLAKE3. The matching seed digests for the two
nonces confirm the intended nonce-independent input.

## Build and device test

Configured with the Visual Studio 2022 x64 generator, the Toolkit overlay
above, `PEPEPOW_CUDA_HOOHASH_STAGE_TESTS=ON`, and Core source path
`D:\Dev\pepepow-deps\PePe-core`. The build compiled the standalone CUDA probe,
the CUDA BLAKE3 stage, the pinned-Core BLAKE3 reference, and CPU oracle.

Both Debug and Release builds succeeded. With
`PEPEPOW_CUDA_REQUIRE_DEVICE=1` and with no no-device skip override, CTest
passed 3/3 in each configuration:

- `hoohash_blake3_stage_full_digest_parity`
- `cuda_device_probe_json_contract`
- `cuda_device_execution_skip_policy`

The direct Debug and Release runs each reported four `LIVE CUDA` full-digest
matches: nonce 6/header, nonce 6/matrix-seed, `UINT32_MAX`/header, and
`UINT32_MAX`/matrix-seed. The device-required setting means no-device fallback
could not satisfy these runs.

The added skip-policy fixture verifies that `cuda_failure` and all other
generic runtime errors cannot be skipped, even in the explicitly enabled
no-GPU CI configuration. The pinned-Core CMake gate checks the exact commit
and rejects tracked or untracked changes before compiling the BLAKE3 oracle.
A local configure with an intentionally incorrect expected SHA failed as
required. A second configure using a pinned Core worktree with a temporary
untracked file also failed as required; the disposable worktree and sentinel
were removed afterward.
